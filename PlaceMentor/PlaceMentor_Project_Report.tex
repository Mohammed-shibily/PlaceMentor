\begin{center}
\Large\textbf{Abstract}
\end{center}

The campus placement process forms a critical bridge between academic institutions and corporate employers. However, managing job postings, student applications, resumes, and interview schedules manually is a decentralized, inefficient, and error-prone process. \textbf{PlaceMentor: Campus Placement Management System} is designed to solve these challenges by providing an integrated, centralized web application that streamlines the entire recruitment lifecycle for students, placement officers, and corporate HR representatives.

The system is developed using the \textbf{Django} backend framework to support rapid, secure, and scalable database operations. It features dedicated user dashboards tailored to specific roles: an Administrative Dashboard for overall oversight, an HR Dashboard for recruiters to post jobs and shortlist candidates, and a Student Portal for tracking job opportunities, managing academic profiles, and bookmarking potential careers. By integrating smart notification engines and dynamic application tracking logic, PlaceMentor vastly reduces the administrative burden on placement cells.

Key functionalities include resume management, real-time application status tracking, and CGPA-based eligibility filters using algorithmic checks to ensure candidates meet precise corporate requirements before applying. Evaluations of the platform demonstrate a highly responsive UI, secure data handling, and a significant reduction in the time required to manage placement drives, thereby democratizing access to job opportunities and enhancing the overall campus recruitment experience.

\chapter{Introduction}

In the competitive modern academic environment, facilitating structured campus placements is essential for ensuring successful student career trajectories. The transition from academic life to professional careers is primarily managed by institutional placement cells. However, coordinating multiple HR recruiters, distributing job descriptions, and evaluating hundreds of student applications simultaneously poses significant logistical challenges when handled manually. \textbf{PlaceMentor} addresses this by providing an organized, robust software layer that automates communication, application screening, and candidate tracking.

\section{Motivation}

The current standard for placement tracking is heavily reliant on spreadsheets, manual email chains, and paper-based resume submissions. This creates an accessibility gap where communication delays cause students to miss key deadlines or updates regarding their application status. The motivation behind \textbf{PlaceMentor} is to eliminate structural delays by offering an instantaneous, self-contained portal where students can build their profile once, and HR personnel can seamlessly review qualified applicants through a centralized dashboard. By automating routine administrative tasks, the system frees up structural bottlenecks so placement officers can focus on corporate relations.

\section{Objectives}

The specific objectives of the PlaceMentor project are defined as follows:

\begin{itemize}
    \item To digitize the entire placement process from job posting to final candidate selection.
    \item To implement tiered user access roles specifically optimized for Students, HR personnel, and Placement Admins via robust Role-Based Access Control (RBAC).
    \item To automate eligibility screening based on strict academic criteria (e.g., mathematical CGPA evaluations) prior to application submission.
    \item To develop a dynamic notification engine keeping students instantly updated on shortlist statuses, interview schedules, and application rejections.
    \item To provide interactive Data Dashboards for HR and Admins to monitor active recruitment drives, candidate pools, and placement statistics.
\end{itemize}

\section{Contributions}

The key contributions of this project are:

\begin{enumerate}
    \item \textbf{Role-Based Dashboard Ecosystem:} Unique, secure interfaces that completely separate student functionalities from administrative and HR controls, maintaining strict data sovereignty.
    \item \textbf{Automated Tracking Pipeline:} A seamless state-management system shifting student applications progressively from ``Applied'' to ``Shortlisted'', and eventually ``Selected'' or ``Rejected''.
    \item \textbf{Smart Notification Engine:} Dynamic alerts bridging communication gaps efficiently without relying on generic, easily missed mass emails.
    \item \textbf{Mathematical Eligibility Function:} Implementation of precise algorithmic rules ensuring unqualified candidates are restricted from applying, saving recruiters substantial review time.
    \item \textbf{Full-Stack Django Integration:} A cohesive system built using Python's Django framework providing a secure Object-Relational Mapping (ORM) backend and robust templating.
\end{enumerate}

\chapter{System Study}

\section{Existing System}

Existing systems in most university placement cells rely on a fragmented collection of generic tools, primarily utilizing Google Forms for data collection, Excel spreadsheets for sorting candidate data, and WhatsApp groups for communication.

The broad limitations of existing systems can be summarized as follows:
\begin{enumerate}
    \item \textbf{Data Duplication:} Students are forced to repeatedly enter primary information, calculate percentages, and upload resumes for every individual job drive.
    \item \textbf{Lack of transparency:} Students often have limited or zero visibility into the real-time status of their application once submitted to the placement cell, leading to anxiety and repeated inquiries.
    \item \textbf{High Administrative Burden:} Placement officers spend extensive time manually verifying that students meet corporate CGPA, graduation year, and arrears criteria using Excel VLOOKUPs or manual cross-referencing.
    \item \textbf{Communication Bottlenecks:} Relying on batch email blasts leads to missed information, poor engagement with crucial placement deadlines, and no automated read-receipts.
\end{enumerate}

\section{Proposed System}

\textbf{PlaceMentor} introduces a centralized, technology-first approach to placement handling. It functions as an integrated job board and applicant tracking system (ATS) contained within the campus network. 

When HR representatives create a dynamic job posting, they can set explicit academic requirements. The system's logical backend instantly filters the applicant pool, disabling the ``Apply'' functionality for students whose academic profiles do not meet the minimum requirements natively. By enforcing structural data relationships, the platform handles complex candidate sorting automatically, reducing manual HR time to a fraction of the original workload. Furthermore, any change in applicant state made by an HR representative immediately emits a notification to the concerned student's dashboard.

\section{Functionalities of Proposed System}

\begin{enumerate}
    \item \textbf{Profile Management:} Students maintain a unified digital resume highlighting their CGPA, technical skills, educational background, and social links (e.g., GitHub, LinkedIn).
    \item \textbf{Job Bookmarking:} Features allowing students to ``bookmark'' specific roles to track upcoming deadlines independently without applying immediately.
    \item \textbf{Algorithmic Eligibility Checks:} Restricts application flow dynamically based on active minimum academic requirements (e.g., CGPA) attached to job profiles.
    \item \textbf{HR ATS Dashboard:} Allows corporate recruiters to post jobs, review tabular lists of applicants, download batched resume files, and update application statuses interactively via Kanban-style flows.
    \item \textbf{Persistent Notifications:} A dedicated alerting ledger utilizing database signals to inform students of critical shortlist updates immediately upon HR action.
\end{enumerate}

\subsection{Python and Django Framework}

Python was selected as the foundational language due to its object-oriented architecture and readability. \textbf{Django 5.x} serves as the overarching monolithic web framework, orchestrating MVT (Model-View-Template) logic. Django provides highly performant synchronous routing and automates request validation. Its built-in Object-Relational Mapper (ORM) securely interfaces Python class models into the database, abstracting raw SQL queries and natively protecting against SQL Injection and Cross-Site Request Forgery (CSRF).

\subsection{Mathematical Formulations}

A crucial component of PlaceMentor is automating the evaluation of candidate eligibility and generating precise notification traces.

\subsubsection{Algorithmic CGPA Eligibility Check}
The system must prevent unqualified students from clogging the application pipeline. Let $C_{s}$ represent the student's current recorded CGPA, and let $C_{req}$ represent the minimum required CGPA for a specific job posting $J_i$. 

The eligibility function $E(S, J_i)$ for a given student $S$ applying to job $J_i$ is defined logically as:
\begin{equation}
E(S, J_i) = 
\begin{cases} 
1 \quad (\text{Eligible}), & \text{if } C_{s} \geq C_{req} \\
0 \quad (\text{Ineligible}), & \text{otherwise}
\end{cases}
\label{eq:cgpa_check}
\end{equation}

In the Django backend, if $E(S, J_i) = 0$, the server intercepts the POST request and raises a validation error, visually disabling the application button on the frontend to prevent redundant processing.

\subsubsection{State-Transition Notification Algorithm}
To keep students informed asynchronously, the system monitors application state changes. Let $\mathbb{A}$ be the set of possible application states: $\mathbb{A} = \{\text{Applied}, \text{Under\_Review}, \text{Shortlisted}, \text{Interview}, \text{Selected}, \text{Rejected}\}$.

When an HR Representative acts, the state of the student's application changes from $s_{old}$ to $s_{new}$ at time $t$. The notification emission function $F_{notif}$ guarantees a message $M$ is written to the database:
\begin{equation}
F_{notif}(S, J_i, s_{old}, s_{new}) \implies M = \text{“Your status for } J_i \text{ is updated to } s_{new}\text{.”} \quad \forall \ s_{old} \neq s_{new}
\end{equation}
This operation executes concurrently utilizing Django Signals (\texttt{post\_save}), detaching the notification generation from the core application save block, ensuring horizontal scalability.

\section{System Architecture}

PlaceMentor is structured strictly as an MVC/MVT (Model-View-Template) application driven by Django's native architecture.

\begin{enumerate}
    \item \textbf{Presentation Tier (Templates):} HTML files enhanced by the Django Template Language logic. It communicates user actions to the backend via standard HTTP POST and GET requests.
    \item \textbf{Logic Tier (Views):} Python-based functions and class-based views that orchestrate the application's domain logic, containing the \texttt{StudentProfile}, \texttt{JobPosting}, and \texttt{Notification} services.
    \item \textbf{Data Tier (Models):} Relational SQL database schema defined entirely in Python classes. The Django ORM synchronizes these abstract models with the underlying database tables automatically.
\end{enumerate}

\section{Module Description}

\subsection{Authentication and RBAC Module}
Security in a multi-tenant university setting requires stringent enforcement. The authentication engine establishes identity natively via Django sessions utilizing PBKDF2 password hashing. Upon login, decorators like \texttt{@login\_required} intersect HTTP requests to ensure users are authenticated. Furthermore, Role-Based Access Control (RBAC) is manually asserted on specialized views (e.g., verifying `request.user.is\_hr` before permitting a user to view the applicant ATS tables), securing the platform against URL manipulation.

\subsection{Student Services \& Discovery Module}
The Student module encapsulates the core candidate experience. It permits students to formulate resilient, digital `CandidateProfiles`. The \textit{Job Discovery Engine} pulls actively listed \texttt{JobPosting} rows and maps them to the frontend using Django Template Language loops via context variables. The logic inherently calculates eligibility using Equation \ref{eq:cgpa_check} and blocks invalid application POST submissions.

\subsection{HR ATS \& Administrative Module}
Functioning as an Applicant Tracking System (ATS), this module allows corporate representatives to review candidates interactively. Recruiters can view summarized data rows describing applicant details, download hosted resumes immediately formatted by the browser natively, and advance candidates manually across recruitment funnels by modifying the \texttt{JobApplication.status} state variable natively rendering updates across the system simultaneously.

\chapter{Results and Discussions}

This chapter highlights the successful outputs from the PlaceMentor platform integration. Continuous functional testing confirms the structural integrity of the Django backend routing, database relations, and user-interface responsiveness.

\section{System Performance and Application Results}

\subsection{Algorithmic Filtering Integrity}
The mathematical implementations defining academic checkpoints behaved flawlessly under simulated mass-applications testing. Upon attempting to submit queries referencing user IDs with cumulative grade metrics beneath HR designations, the system consistently returned mathematical failure cascades, prohibiting redundant DB rows natively and preserving ATS query clarity. Thus, Equation \ref{eq:cgpa_check} functioned robustly under realistic system stress.

\subsection{Web Application Responses}
The full-stack application was deployed against a suite of functional interactions. 
\begin{itemize}
    \item \textbf{High-Speed Routing:} Complete job tracking rendering executes smoothly due to optimized Django database lookups.
    \item \textbf{Role Segregation:} Security tests confirmed that simulated Student accounts attempting to execute GET requests on \texttt{/hr-dashboard} views received immutable HTTP 403 Forbidden redirects, thereby preserving data integrity.
    \item \textbf{Static File Management:} Resume uploading mechanisms correctly parse, namespace, and save large PDF binaries into static file storage securely, segregating them correctly against individual profile UUID definitions.
\end{itemize}

\section{Discussions}

\subsection{Strengths of the Proposed System}
\begin{enumerate}
    \item \textbf{Centralized Command Hub:} PlaceMentor eliminates the chaotic workflow fragmentation typical of generic placement mechanisms by centralizing application submission, PDF handling, and recruiter interaction natively.
    \item \textbf{Algorithmic Optimization:} Utilizing math-based query boundaries severely decreases recruiters' administrative workload, saving them from cross-checking credentials manual.
    \item \textbf{High Engagement UX:} By integrating native notifications that mimic social-media alert paradigms, candidates remain deeply engaged and are less likely to miss critical, time-sensitive corporate checkpoints.
\end{enumerate}

\subsection{Limitations of the Proposed System}
\begin{enumerate}
    \item \textbf{Server Architecture Constraints:} The platform currently utilizes SQLite inherently locked via synchronous file writing architectures. Shifting to tens of thousands of simultaneous users during massive placement drives demands refactoring the database target towards PostgreSQL on cloud clusters.
    \item \textbf{Lack of External Integrations:} The system lacks integrated, synchronous communication layers (e.g., live chat or live video call mechanisms), bounding the system purely to textual tracking and alerting functions.
\end{enumerate}

\chapter{Conclusion}

PlaceMentor establishes a functional, streamlined paradigm for optimizing university campus placements. By unifying distinct datasets—candidate profiles, corporate job constraints, and active applications—the system ensures transparency and dramatically cuts operational friction. 

The successful deployment of a mathematical CGPA logic filter algorithm proves that applying systematic software rules natively eliminates enormous manual processing overhead. Furthermore, the robust full-stack architecture built atop the Django ecosystem ensures that interactions remain strongly protected under stringent Role-Based Access Controls. 

Ultimately, PlaceMentor functions dynamically as an institutional bridge. It democratizes the interface connecting students to corporate recruiters while allowing placement officers intuitive oversight regarding critical hiring drives happening throughout their campus network.

\section{Future Scope}

Continuous improvements to the platform offer several avenues for broader impact:

\begin{itemize}
    \item \textbf{API Communication Overhauls:} Transitioning from on-site dashboard notifications to fully integrated Twilio AWS interactions, automatically pushing SMS or WhatsApp notifications to candidates' phones when their application state transitions.
    \item \textbf{Automated Resume Parser Engine:} Integrating internal NLP/OCR (Natural Language Processing) tools capable of automatically parsing unstructured student resume PDFs to proactively fill out the `CandidateProfile`, decreasing initial barrier to entry.
    \item \textbf{Coding Sandbox Integrations:} Building an isolated coding testing environment directly into the HR Applicant Tracking board, so recruiters can issue algorithmic competency tests immediately before allocating interview statuses.
\end{itemize}

from django.shortcuts import get_object_or_404, redirect
from django.contrib import messages
from .models import JobPosting, Application, Profile

def apply_for_job(request, job_id):
    """
    Evaluates candidate credentials utilizing Equation 4.1.
    Restricts DB writes logically if math boundaries fail.
    """
    job = get_object_or_404(JobPosting, id=job_id)
    student_profile = get_object_or_404(Profile, user=request.user)

    # Formulation E(S, J_i) implementation bounds
    if student_profile.cgpa < job.min_cgpa:
        messages.error(
            request, 
            "Eligibility Alert: Current CGPA metrics insufficient for application."
        )
        return redirect('job_details', job_id=job.id)

    # Proceed tracking mechanism
    Application.objects.create(applicant=request.user, job=job)
    messages.success(request, "Candidate placement initialized perfectly.")
    return redirect('student_dashboard')

from django.db import models
from django.db.models.signals import post_save
from django.dispatch import receiver

class Application(models.Model):
    STATUS_CHOICES = (
        ('Pending', 'Pending'),
        ('Shortlisted', 'Shortlisted'),
        ('Selected', 'Selected')
    )
    applicant = models.ForeignKey(User, on_delete=models.CASCADE)
    job = models.ForeignKey(JobPosting, on_delete=models.CASCADE)
    status = models.CharField(max_length=20, choices=STATUS_CHOICES, default='Pending')

@receiver(post_save, sender=Application)
def create_state_notification(sender, instance, created, **kwargs):
    """
    Implements F_{notif} mathematical trigger asynchronously upon save signals.
    """
    if not created: 
        Notification.objects.create(
            user=instance.applicant,
            message=f"Interaction Logged: Your ATS tracker status for {instance.job.title} updated to: {instance.status}"
        )
\end{lstlisting}
